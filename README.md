## 🔍 v1.5.0：全文件搜索常开 · 字号可自定义 · 版本库文本压缩

- **搜索框右边现在选「范围」**：PPT / Word / PDF / 全部文档 / **全部文件（仅文件名）**。「索引所有文件」那个设置开关撤掉了——全盘文件名盘点变成常开能力，想按名字找任意文件，当场换个范围就行，不必先去设置里找开关、再等一轮重扫。全盘盘点只登记文件名不解析内容，所以这个范围下只能按名字搜，限制直接写在选项文字里。
- **代价照实说**：剪枝后要登记 1,750,775 个文件（其中 PPT / Word / PDF 只有 2,155 个），单行 731 字节，索引库约增加 **1.19 GB**；升级后首次启动会安排一轮全盘重扫（约 2.4 分钟遍历 + 1.8 分钟写库，低优先级后台跑，期间照常能搜）。想要轻量就把范围留在 PPT，搜索不会因此变慢。
- **界面字号除了三档预设，还能自定义 0.50~2.00 倍**（步进 0.05）。两端刻意夹死：再往外已经不是能用的界面了。搜索行会跟着字号一起长高，100% 及以下逐像素还是老样子。
- **版本库的文本零件改为压缩存放**。真实版本库只读盘点：48,775 个对象 / 3,175 MB，其中 `.xml` / `.rels` 占 889.9 MB（个数占 77%），抽样实压到 **11%**——全部换血后可省 **788 MB**。设计上只加不改：文件名仍是**未压缩内容**的哈希（`.z` 只是后缀），存量零件一个不动（所以这 788 MB 随你继续改稿逐步兑现，不是升级当天到账），压完必须解压回来逐字节比对才允许落盘——压缩路径就算彻底坏掉，最坏也只是「没压」，不可能存进一个解不回原内容的文件。
- **留底顺带更快了**：12 份真稿首次留底 13.7 s → 9.2 s。文本零件占对象数量的 77%，改走内存路径后每个零件只落一次盘；媒体零件仍走流式，峰值内存不变。

## 🛡️ v1.3.2：版本库独立复审 · 数据安全与 PowerPoint 共存

- 恢复路径改为“先验证恢复点、最后原子替换”：当前 PPT 已损坏时仍能救回；恢复点被换成另一份可打开的文件、旧版 full hash 不一致、对象缺失时一律拒绝覆盖。
- 原位恢复会通过现有 PowerPoint 的文稿集合做只读审计，并在原子替换前再次检查；无法证明目标未打开就失败关闭，不靠 Windows 共享写句柄猜测。
- 版本库迁移逐文件比对字节、SQLite 做结构自检，并在新库重连与配置落盘成功前保留源库回滚副本；迁移与正在进行的保存自动串行，失败后旧库仍可继续留底。
- 手动清理失效版本不再绕过管理器锁，杜绝把“对象已写、DB 未提交”的在途快照误当孤儿删除；容量驱逐先过结构安全门并先提交 DB、后删 artifact，中途强杀只留下可回收孤儿，不会留下指向缺件的存活版本；暂时离线/已删除文档在宽限期内仍保留最后恢复点。
- 新留底、恢复以及跨盘迁移旧对象全部流式处理，256 MB 稿件峰值 RSS 仅增加 3.1 MB；500 次真实 ZIP 保存后峰值 RSS +6.8 MB、最终 Private Bytes +2.7 MB、句柄 +2、版本稳定收敛到 100。
- 真实 PowerPoint 共存 E2E 覆盖 watcher 自动留底、留底中再次保存、隐藏只读历史预览、窗口/活动文稿/保存状态不变，以及打开状态下拒绝恢复，16/16 全部通过。

## 🛡️ v1.0.15：PowerPoint 开着也能安全预览

- 用户正在编辑 PPT 时，右侧预览可直接借用现有 PowerPoint COM，但只打开本地只读、无窗口的临时快照；原文件、活动文稿、保存状态和显示设置都不改。

- 已有索引升级后自动安排一次低优先级补漏，此后每 7 天在空闲窗口完整枚举固定磁盘；自动任务固定单 worker，搜索或文件操作进行中自动延期，无变化时不做全库聚类和数据库维护。
- 右侧预览只预取当前翻页方向的一页，已有 960px 缓存先瞬时显示；大窗口停留 160ms 后才补高清，连续翻页会取消未开始的高清任务，已达目标清晰度的缓存不再重复调用 PowerPoint。
- 搜索结果改为紧凑纯文本卡片，不再加载每一项的封面图；搜索、排序和滚动产生 0 个结果缩略图任务，把图片解码与渲染预算留给用户点击后的右侧大图和相邻页。
- 胶片报告增加“创作足迹”与“胶片 DNA”：连续活跃期、最忙月份、平均页数、文字密度、短篇/长篇、复用家族和正文索引健康度；范围切换在 SQL 层先过滤并复用已生成报告。

## 🔎 v1.0.8 搜索语义与预览快切

- 多词搜索先按完整短语排序：`AI SP` 优先命中连续的 `AI SP`，同时保留 `AI` 与 `SP` 同页分开出现的召回兜底。
- 新增“大小写”开关，默认不区分；开启后文件名与页内容都按原文大小写验证。
- 相关度硬分层扩展为“文件名完整短语 > 内容完整短语 > 去分隔符全字 > 部分匹配”，并修复 `AI SPARK` 被误判成 `AI SP` 全字命中的边界问题。
- 翻页预取只复用本工具已打开的安全快照，绝不为后台任务启动/附着 PowerPoint 或打开新演示文稿；单 COM 串行、最多两页、120 ms 可取消空闲窗。
- 优先预取当前翻页方向的相邻页和下一命中页；右侧高清预览完成后直接复用为当前结果卡缩略图，不增加一次 COM 渲染。

## ⚡ v1.0.7 流畅度升级

- 相关度按“文件名完全匹配 > 内容完整匹配 > 部分匹配”排序，并支持主排序 + 次排序组合。
- 大结果集只创建首屏卡片，其余按需加载；排序和筛选不再反复重建数百个 QWidget。
- 搜索状态与索引统计解耦，文件变化引发的重复搜索合并到空闲窗口。
- 预览复用安全快照、只预取一页；超时不重复等待，后台不再启动时自动预热 PowerPoint。
- 非空索引启动时不再周期性遍历全盘；只核对已索引路径及其直接父目录，避免启动后长期占满一个 CPU 核。关闭期间在全新目录创建的文件、或离线删除的文件，可用“重新扫描全盘”同步。
- 首次建库若被中断，待解析文件会在下次运行中按节流队列持续补齐，无需反复重启；需要立即补全时仍可手动重新扫描。

## 🚀 用法

绿色免安装，双击 `PPT Doctor.exe` 即用。首次自动后台全盘建索引（边扫边搜）。

源码运行：

```bash
uv run python -m pptx_finder
```

打包：

```bash
uv run pyinstaller pptx-finder.spec --noconfirm    # → dist/PPT Doctor/PPT Doctor.exe
```

## 📁 数据

- 索引库 / 版本库：`%LOCALAPPDATA%\pptx-finder\`
- 索引范围默认覆盖所有本地固定磁盘；在「设置 → 功能 → 索引范围」里可添加自定义目录或网络路径（`\\server\share\dir`），保存后与固定盘一起被索引（增量语义，重启后生效）；网络路径当前不可达也可保存，可达时自动纳入，其内容变化最坏约一周后才随完整扫描被感知，重启应用可加速
- 也可用环境变量 `PPTX_FINDER_ROOTS` 限定（os.pathsep 分隔）：未配置自定义根时它是完整索引范围；已配置自定义根时它作为追加项合并去重

## 🛡️ v1.0.5 版本守护

- 保存事件先捕获为稳定临时副本；PowerPoint 原子替换或同步盘改写期间，不会把两次保存混成一个版本。
- 每个恢复点都是完整 OpenXML 包快照：跨文档对象去重，但恢复不依赖补丁链。
- 恢复/导出先在目标同目录重组、解析并核对内容哈希，全部通过后才原子替换；失败不动现有文件。
- 启动快速检查清单和对象引用，设置页可手动执行全对象哈希深检；损坏恢复点自动隔离，不再参与恢复、搜索入口或复制分支。
- 离线巡检按游标轮转覆盖全部受管文档，并能重新接管软件关闭期间在原路径重建的文件。
- 默认每份 PPT 保留 100 版：先保每次编辑会话的里程碑，再保近期细粒度保存；复制分支的基线永久受保护。
- 重型迁移与 GC 七天节流；生产规模快速审计由重复磁盘探测改为一次对象集合扫描。
